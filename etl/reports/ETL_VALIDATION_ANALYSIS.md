- **根本原因**: 
  - ETL系统 `etl_main.py` 中的去重逻辑可能存在问题

- **建议**:
  1. 立即停止ETL导入，避免产生更多重复数据
  2. 清理数据库中的重复记录
  3. 检查 `save_to_database()` 函数的去重逻辑
  4. 在数据库层面添加唯一约束检查

#### 2. 数据逻辑不一致（严重）🚨
- **问题描述**: 转化率计算与实际数据严重不符
  - **store_entry_rate**: 59.54% (312/524条记录) 不匹配
  - **order_conversion_rate**: 95.29% (486/510条记录) 不匹配
- **不匹配示例**:
  ```
  记录的入店转化率: 0.07%
  计算的入店转化率: 7.4% (入店人数59 / 曝光人数797 * 100)
  
  记录的下单转化率: 0.22%
  计算的下单转化率: 22.4% (下单人数125 / 入店人数558 * 100)
  ```
- **根本原因**: 
  - 转化率字段可能在源文件中已经是百分比（0.22表示22%）
  - 或者在字段映射过程中被错误处理
  - 需要检查 `field_mapping.py` 中的字段映射是否正确
- **建议**:
  1. 重新检查源文件中的转化率字段格式
  2. 修正字段映射逻辑
  3. 确认转化率数据是百分比数值还是小数

2. **清理重复数据**
   ```sql
   -- 识别重复记录
   SELECT date, platform, brand_store_name, COUNT(*) as cnt
   FROM daily_orders
   WHERE date BETWEEN '2026-01-11' AND '2026-01-18'
   GROUP BY date, platform, brand_store_name
   HAVING cnt > 1;
   
   -- 删除重复记录（保留最新的）
   DELETE t1 FROM daily_orders t1
   INNER JOIN (
       SELECT MIN(id) as keep_id, date, platform, brand_store_name
       FROM daily_orders
       WHERE date BETWEEN '2026-01-11' AND '2026-01-18'
       GROUP BY date, platform, brand_store_name
       HAVING COUNT(*) > 1
   ) t2 ON t1.date = t2.date 
         AND t1.platform = t2.platform 
         AND t1.brand_store_name = t2.brand_store_name
         AND t1.id != t2.keep_id;
   ```
